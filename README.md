# MOEX Watch 0.6.7

C++20 / Win32 приложение для Windows 10 x64. Включает свечной график, технические индикаторы, блокнот закрытых сделок, настраиваемые сигналы и проверку стратегии на истории.

## Готовые сборки и история версий

Все опубликованные версии доступны в [GitHub Releases](https://github.com/avertyu59-blip/MOEXWatch/releases).
Для запуска скачайте **MOEXWatch-<версия>-Windows-x64.zip**, распакуйте его и запустите **MOEXWatch.exe**. Среда выполнения MSVC включена в EXE; устанавливать Build Tools для готовой сборки не требуется.
Каждой версии соответствует отдельный тег и исходники. Предыдущие опубликованные выпуски сохраняются; файлы опубликованной версии автоматически не заменяются. Текущие выпуски помечаются как тестовые (Pre-release).

Автопубликация запускается при изменении `VERSION.txt` в `main` или текущей ветке разработки `feature/0.3.1-position-levels`, а также по тегу `v<версия>`. Перед публикацией выполняются сборка MSVC и CTest. Добавление новой версии не удаляет старые релизы.

## Техническое обновление 0.6.7 — управляемая загрузка

Загрузки акций, IMOEX, дивидендов и бэктеста теперь принадлежат приложению: при закрытии оно запрашивает отмену и завершает работников перед уничтожением состояния. Отсоединённых потоков больше нет. Кнопка **«Отменить загрузки»** отменяет активные сетевые задачи; резервное копирование завершает работу либо отменяется при закрытии. Результаты передаются через очередь в UI-поток. Отменённый или устаревший ответ не заменяет текущие данные.

Транспорт использует асинхронный WinHTTP. Отмена прерывает ожидание заголовков или чтение тела ответа. Временные ошибки соединения и HTTP 408/429/500/502/503/504 допускают максимум три попытки с паузами 1 и 2 секунды; прочие HTTP-ошибки и ошибки проверки формата повторно не запрашиваются. Паузы тоже отменяемые. Лимит одной попытки — 20 секунд, ответа — 2 МБ. Проверяются тикер, числовые поля, OHLC, объёмы и порядок дат; кэш свечей заменяется после получения полной проверенной истории.

Кнопка **«Журнал ошибок»** открывает `%APPDATA%/MOEXWatch/logs/diagnostic.log`. В нём время UTC, номер запроса, источник, этап, попытка, код и длительность; без тела ответа, списка операций и URL с параметрами. Хранятся текущий журнал и две ротации примерно по 256 КиБ. Ошибка записи журнала не прерывает работу приложения.

Проверены расчёты, состояния, хранилище, CSV, сигналы, идентификаторы, страницы и графики Win32, политика повторов, отмена ожидания и закрытие окна во время загрузки. Отдельный Windows-тест обращается к локальному HTTP-серверу и отменяет WinHTTP до заголовков и во время чтения ответа. Доступность внешних поставщиков этими воспроизводимыми тестами не гарантируется.

## Техническое обновление 0.6.6 — постоянные ID операций и позиций

Каждая операция получает случайный UUID v4 (`id`), каждый цикл позиции — отдельный `position_id`. Усреднение и частичные продажи сохраняют цикл; полное закрытие и следующая покупка открывают другой цикл даже в один день. UUID сохраняются, а не вычисляются из тикера/даты/номера строки. Порядок исполнения задаётся датой и сохранённым `sequence`; сортировка таблицы его не меняет. Счётчик порядка хранится отдельно и не уменьшается после удаления операций.

Стоп-лосс и тейк-профит связаны с `position_id`. Закрытые уровни сохраняются в журнале, но не переходят новой покупке. При удалении первой покупки ID сохраняется у оставшихся покупок цикла, если история остаётся допустимой. Продажа без остатка и объединение двух существующих ID позиций блокируются. Если удаление меняет границы или убирает цикл, приложение показывает ID и последствия и запрашивает подтверждение. Отмена сохраняет журнал. Строки таблиц сопоставляются с постоянными ID; ID и порядок доступны в дополнительных столбцах справа.

### Миграция и резервная копия

Новый основной файл — `%APPDATA%/MOEXWatch/portfolio_journal_v2.csv`: операции, уровни, несопоставленные старые уровни и счётчик порядка в одном версионном файле. Они записываются атомарно вместе. Файл содержит заголовки разделов и итоговые счётчики для проверки целостности.

При первом запуске со старым портфелем приложение проверяет историю, создаёт и проверяет резервную копию, назначает ID и сохраняет новый журнал. Старые `portfolio_transactions.csv` и `position_levels.csv` остаются нетронутыми как исходный снимок миграции; дальнейшие изменения идут в новый файл. Повторный запуск использует уже сохранённые ID. Ошибка резервирования/миграции не заменяет старые файлы. Если новый журнал повреждён, приложение блокирует запись и сообщает об ошибке, а не подставляет молча старый снимок. Лимит журнала — 4 МБ; превышение блокирует запись до изменения данных, чтобы не создать файл, который нельзя загрузить.

Если старые уровни по тикеру и дате подходят нескольким циклам либо ни одному, они сохраняются как **несопоставленные**. Их количество видно в сводке портфеля. Выберите открытую позицию и нажмите **«Сопоставить уровни»**: диалог покажет старые цены/дату и ID выбранного цикла. Только явное подтверждение привязывает уровни; «Нет» переходит к следующей записи, отмена сохраняет их отдельно. Связи с закрытыми циклами также сохраняются, даже если цикл удалён из журнала; автоматически переназначать их нельзя.

Резервная копия включает новый журнал. **Для отката используйте подходящую резервную копию целиком:** версии до 0.6.6 не читают новый файл и покажут старый снимок. При восстановлении копии без `portfolio_journal_v2.csv` предварительно переместите текущий новый журнал в отдельную безопасную папку при закрытом приложении; иначе он останется основным. Инструкция включена в `RESTORE.txt` новых копий.

### CSV и дивидендные связи

Экспорт работающего портфеля содержит 9 столбцов:

```text
date;ticker;side;quantity;price;commission;id;position_id;sequence
```

Прежний CSV из 6 столбцов по-прежнему импортируется. Для него сохраняются проверка совпадений по полям и возможность включить одинаковые реальные операции; ID назначаются при принятии в журнал. В новом формате существующий ID с тем же содержимым всегда пропускается, даже при включённом флажке совпадений. Тот же ID с другими полями, позицией или порядком — конфликт и блокировка всего импорта. Разные ID обозначают разные операции, даже если цены и количество одинаковы. UUID — канонические строчные UUID v4, порядок — положительное целое число.

Импорт сохраняет предоставленные ID и порядок. Противоречивые границы циклов или одинаковый `sequence` у разных операций блокируют импорт; приложение не перенумеровывает их молча. Таким образом, два независимых журнала с собственными одинаковыми порядковыми номерами могут потребовать согласования перед объединением. Предпросмотр показывает ID, порядок, дубликаты и конфликты. CSV экспортирует операции, а не уровни и прочие данные: полная резервная копия — отдельная функция. Удалённую операцию можно вернуть из своего экспорта с исходным ID, если восстановленная история согласована.

Ожидаемые дивиденды теперь возвращают детализацию по `position_id` на последнюю допустимую дату покупки, включая цикл, закрытый после этой даты. В таблице показана связь ожидаемой суммы с ID позиции. Это всё ещё ожидание по полному журналу, а не фактическое поступление; запись полученных дивидендов и налоги по ним в этот этап не входят.

Проверки включают несколько циклов внутри дня, усреднение/продажи, сохранение/перезапуск, миграцию с резервированием и её повторный запуск, неоднозначные уровни, повреждённый файл, сохранение прибыли, CSV-конфликты/повторный импорт/восстановление удалённой операции и дивидендные связи. Win32-тесты проверяют выбор после сортировки, сохранение ID при удалении и отсутствие переноса уровней в новый цикл. Полного визуального прохода Windows 10 при всех DPI здесь нет.

## Техническое обновление 0.6.5 — явное состояние приложения и страниц

В 0.6.3 глобальные UI-переменные уже были заменены владельцем `Application`. В 0.6.5 оставшиеся общие данные распределены по именованным состояниям, а выбор бумаги и применение обновления получили явные точки входа.

| Состояние | Содержимое |
|---|---|
| `ApplicationState` / `MarketState` | Бумаги, история IMOEX, актуальность данных и жизненный цикл обновления |
| `PersistenceState` | Блокировка записи после ошибки пользовательских файлов |
| `ShellState` | Главное окно, шрифт, навигация и общие контролы |
| Состояния вкладок | Собственные поля, контролы, сортировки и подавление уведомлений во время заполнения |
| `DividendsState` | Независимая бумага дивидендного окна, его график, период и номер запроса |

Выбор аналитики хранится по тикеру (`InstrumentSelection`), а не по позиции в векторе. `select_instrument()` используется при переходах из портфеля и истории сигналов. При сортировке/обновлении выбор сохраняется. Если фильтр скрывает выбранную бумагу, выбирается первая подходящая; при пустом фильтре таблица и график показывают отсутствие данных, а тикер сохраняется до возвращения подходящих строк. Дивидендное окно не меняет бумагу вслед за обычным выбором в аналитике. При удалении его бумаги окно закрывается.

`MarketState::begin_refresh()` выдаёт номер запроса; `apply_refresh()` применяет только текущий ответ. Запоздавший или повторный ответ не меняет данные и не разблокирует новый запрос. Повторное нажатие/таймер во время загрузки объединяются в одно последующее обновление. Изменение состава наблюдения во время загрузки делает старый снимок неприменимым: после его завершения запускается новый запрос. Это защищает от применения старых котировок к удалённой и заново добавленной бумаге. Редактирование цели не отменяет загрузку: результат меняет только рыночные поля и сохраняет текущую цель и дивиденды.

Применение результата и обновление представлений разделены: `apply_market_refresh()` → `refresh_market_views()`. Они сохраняют активную вкладку, выбранную бумагу и период графика. У каждой страницы свой `ScopedViewUpdate`: заполнение/сортировка временно подавляет её уведомления, вложенность и досрочный выход безопасны. Общего флага заполнения и общей карты сортировок больше нет.

Состояние меняется в UI-потоке; фоновые потоки получают копии данных и возвращают сообщения. `moex_state` и `app_state_tests` собираются без Windows; режим `MOEX_DOMAIN_ONLY=ON` теперь проверяет и расчёты, и переходы состояния. Тесты охватывают изменение состава списка, удаление/повторное добавление, устаревшие ответы, сохранение целей/дивидендов и независимость экземпляров. Win32-тесты проверяют сортировку/выбор/переходы, восстановление флагов, сохранение вкладки/периода и состояние кнопки при старом ответе.

Это дальнейшее разделение ответственности, а не полная изоляция контроллеров: страницы пока принадлежат общему `Application`. Редактируемые модели доступны владельцу для ввода/хранения; структурные изменения списка во время работы проходят через `MarketState::add/remove`. Формулы и форматы пользовательских файлов сохранены. Управляемая отмена сетевых потоков и закрытие при активной сети остаются отдельным этапом.

## Техническое обновление 0.6.4 — расчёты отдельно от интерфейса

Расчётная библиотека `moex_domain` собирается без Win32, сетевых запросов, провайдеров и файлового хранилища. Общие структуры находятся в `market_types.hpp`; `market_core.hpp` сохраняет совместимость существующих вызовов.

| Модуль | Расчёты |
|---|---|
| `portfolio_calculations` | Закрытые сделки и их итоги, средняя цена, частичные продажи, прибыль, доли позиций |
| `indicators` | SMA, RSI, ATR, объёмы и нормированное сравнение с индексом |
| `signal_rules` | Фильтры и условия «любое/все»; используются аналитикой и бэктестом |
| `backtest` | Исторический прогон с комиссией и сравнением с индексом |
| `dividend_calculations` | Последняя дата покупки по переданному календарю, доходность и ожидаемое право по журналу |

В окне дивидендов добавлен столбец **«Ожидается по журналу»**: количество акций и сумма до налогов для утверждённой выплаты в RUB. Расчёт использует полный журнал операций до последней допустимой даты покупки. Если дата ещё не наступила, показывается прогноз по операциям на сегодня. Продажа после последнего дня покупки не уменьшает ожидаемое количество по событию; покупка после него не увеличивает. Порядок операций внутри дня сохраняется. Устаревшее событие, конфликт с эмитентом, неподтверждённая выплата, неполный календарь или некорректные операции дают «н/д» с причиной.

Это оценка по вашему полному журналу, а не подтверждение от брокера и не факт поступления денег. Шорты, перевод бумаг между счетами и прочие операции вне модели журнала не учитываются. Ожидаемые дивиденды не добавляются к фактической прибыли или бэктесту. Покрытие встроенного календаря остаётся ограниченным 2026 годом; другие даты не угадываются. Модель налога прежнего блокнота закрытых сделок остаётся оценкой по отдельным сделкам, без годового сальдирования.

В интерфейсе остались ввод, отображение, сохранение и уведомления; итоги сделок и дивидендная доходность теперь вычисляются в ядре. Некорректные необходимые цены и объёмы не превращаются в значения индикатора. Для корректных входных данных формулы сохранены, пользовательские форматы файлов не меняются.

Проверка расчётов без сборки приложения:

```sh
cmake -S . -B domain-build -DMOEX_DOMAIN_ONLY=ON
cmake --build domain-build --config Release
ctest --test-dir domain-build -C Release --output-on-failure
```

`domain_tests` связан только с `moex_domain` и проверяет прибыль/комиссии, частичные продажи, пропущенные котировки, индикаторы, сигналы, бэктест и дивидендные границы. CI отдельно собирает расчёты на Linux; Windows проверяет всю программу и реальные скрытые контролы, включая отображение итоговой прибыли и дивидендной оценки. Это автоматические проверки, а не полный визуальный проход на Windows 10 при всех DPI.

## Техническое обновление 0.6.3 — модули вкладок

Интерфейс разделён по вкладкам без изменения финансовых формул и форматов пользовательских файлов. В `main.cpp` остался запуск приложения; `ui_shell.cpp` создаёт главное окно, переключает страницы и координирует обновления.

| Модуль | Ответственность |
|---|---|
| `ui_backtest.cpp` | Параметры, запуск и результат бэктеста, команды и размер вкладки |
| `ui_signals.cpp` | Условия, совпадения, уведомления и подключение истории |
| `ui_portfolio.cpp` | Позиции, операции, уровни, CSV, команды и размер вкладки |
| `ui_trades.cpp` | Прежний журнал закрытых сделок |
| `ui_charts.cpp` | Наблюдение, фильтры, выбор бумаги, цели и аналитика |
| `ui_chart_render.cpp` | Общая отрисовка цены, IMOEX, объёмов и RSI |
| `ui_dividends.cpp` | Отдельное окно дивидендной аналитики |
| `ui_common.cpp` | Общие средства Win32, форматирование и сортировка |

У каждой основной вкладки свой заголовок состояния. Объект `Application` владеет состояниями и общими рыночными данными; изменяемых глобальных переменных интерфейса больше нет. Контролы явно регистрируются у своей страницы, без скрытых флагов построения. Оконные сообщения маршрутизируются к владельцу окна; рабочие потоки по-прежнему получают копии входных данных и отправляют результаты в UI-поток.

Перенос выполнен последовательно: бэктест → сигналы → портфель → графики. Для каждого этапа создан отдельный коммит и выполнены Windows MSVC/CTest. Добавлен `ui_pages_tests`: реальные скрытые Win32-контролы, переключение и видимость страниц, размеры, отсутствие перекрытия кнопок бэктеста, сохранение результата, сигналы без дублей, усреднение/частичная продажа, удаление после сортировки, уровни позиции, фильтры и отрисовка четырёх графиков во всех периодах. Итоговые проверки также охватывают применение обновления на другой вкладке и привязку сообщений к экземпляру приложения.

Тесты не обращаются к реальному портфелю или сети. Это автоматическая проверка компонентов на Windows Server 2022, а не полный визуальный проход на Windows 10 при всех настройках DPI. Форматы файлов, источники, формулы и ограничения предыдущих версий сохранены. Отмена сетевых запросов и переделка существующего механизма фоновых потоков в этот перенос не входят.

## Наблюдение 0.6.2

### Сортировка отображения

Заголовки таблиц наблюдения, закрытых сделок, открытых позиций, операций портфеля, технических сигналов и дивидендов переключают возрастание/убывание. Стрелка показывает направление. Числа сравниваются численно, неизвестные значения остаются в конце при обоих направлениях. Сортировка сохраняется при обновлении таблицы в текущем сеансе, но не после перезапуска. Сравниваются отображаемые значения; округлённые равные значения сохраняют взаимный порядок.

Сортировка **не меняет порядок операций в модели и файлах**: внутридневная последовательность, прибыль и бэктест от неё не зависят. Выбор бумаги, удаление операции и открытие источника используют идентификатор исходной записи, а не визуальный номер строки. История сигналов и список ценовых условий также сортируются; предварительный просмотр CSV остаётся в порядке строк файла.

### Ценовые условия и история

Новая вкладка **«История сигналов»** содержит фильтр по тикеру, журнал и кнопку **«Ценовые уведомления»**. В окне условий можно добавить несколько уровней для одной бумаги: `цена <= уровень` либо `цена >= уровень`, включить/выключить или удалить условие. Изменения действуют только после «Сохранить изменения»; «Отмена» их не применяет. Для изменения уровня удалите старое условие и добавьте новое. Не более 100 условий. Проверяются только бумаги, которые есть в списке наблюдения.

- При запуске приложения, добавлении/включении/изменении условия и повторном добавлении тикера первый **свежий** ответ задаёт исходное состояние. События о текущем совпадении при старте не рассылаются.
- Затем событие записывается при переходе из состояния «условие не выполнено» в «выполнено», включая точное равенство уровню. Повторные обновления внутри условия не создают новые события. Для повторного срабатывания сначала нужен свежий выход из условия. Каждый ценовой уровень проверяется отдельно.
- Техническая история следует прежней логике группы «любое/все условия»: записывается вход группы в совпадение. Изменение набора причин, пока группа уже совпадает, не является отдельным событием. Изменение технических правил сбрасывает их исходное состояние; переключение всплывающих уведомлений или интервала обновления его не сбрасывает.
- Сбой сети, отсутствующие данные, старые котировки и недоступная история не меняют соответствующее предыдущее состояние. Восстановление загрузки поэтому не создаёт повторный сигнал само по себе. Начальная ошибка не считается успешной исходной точкой.
- Для событий дополнительно проверяются `SYSTIME` и `UPDATETIME` MOEX: полный источник и время котировки должны быть не старше 20 минут относительно текущего времени (МСК, UTC+3); предусмотрен небольшой допуск часов в будущее 90 секунд. Переход через полночь учитывается. Обычная задержка публичного ISS 15 минут допустима, один HTTP 200 не доказывает свежесть. При отсутствующем времени источника события не создаются.
- В журнал попадают время **обнаружения** в МСК, тикер, тип, условие/причины с порогами, наблюдавшаяся цена, время котировки и SYSTIME. Это не точное время биржевого пересечения. Между проверками цена может пересечь уровень и вернуться — такое событие дневными/периодическими запросами не восстанавливается.
- История записывается независимо от переключателя **«Всплывающие уведомления»** на вкладке «Сигналы». Этот переключатель общий для технических и ценовых событий. Windows может скрывать всплывающие сообщения; запись истории не означает, что пользователь увидел сообщение.
- Хранятся последние 2000 событий в `%APPDATA%\MOEXWatch\signal_history.csv`; условия — в `price_alerts.csv`. Оба файла включены в резервные копии. История после перезапуска не переигрывается в уведомления; состояния переходов заново устанавливаются по первому свежему ответу. Удалённые из наблюдения тикеры остаются доступными в фильтре исторических записей.
- Двойной щелчок по событию открывает бумагу в аналитике и снимает текущий фильтр наблюдения. Если бумага удалена, приложение предлагает добавить её в наблюдение; скрытого добавления нет.
- Ошибка записи истории помечается явно: новые события остаются в памяти, запись повторяется при следующем обновлении. Повреждённые файлы наблюдений не заменяются пустыми; сохранение этого раздела блокируется до восстановления, оригиналы остаются для резервирования. Это не мешает смотреть уже загруженные данные и журнал в памяти.

Проверка работает **только пока приложение запущено**, при ручном обновлении или включённом автообновлении (15/30/60 минут). Задержка обнаружения складывается из интервала проверки и задержки источника. Уведомления и журнал описывают наблюдения, не отправляют заявки и не подтверждают прибыльность стратегии.

Проверки 0.6.2: тесты переходов/перезапуска/сбоев, времени МСК и полуночи, сохранения правил и событий, независимости истории от настройки уведомлений и числового порядка. Windows `gui_sort_tests` создаёт скрытые настоящие ListView, проверяет сортировку/сохранение выбранной записи, создание страницы истории, фильтр и открытие правильного тикера. Это ограниченная проверка компонентов, а не полноценная визуальная проверка Windows 10.

## Удобный портфель 0.6.1

- В открытых позициях добавлен столбец **«Доля, %»**: рыночная стоимость бумаги / стоимость всех открытых позиций × 100. Расчёт относится только к акциям в этом журнале, без денежных остатков, налогов и других счетов. Если хотя бы одна открытая позиция не оценена или котировка устарела, доли скрыты («—»), а общая стоимость помечена как неполная/устаревшая оценка. Неполная часть портфеля не нормируется к 100%.
- На вкладке «Портфель» кнопки **«Импорт CSV»** и **«Экспорт CSV»**. Экспорт содержит операции BUY/SELL, а не старый журнал закрытых сделок, котировки или рассчитанную прибыль. Формат UTF-8 с BOM, разделитель `;`, десятичная точка, точность 17 значащих цифр. Имя и папка выбираются пользователем; экспорт в рабочую папку APPDATA/MOEXWatch и её резервные копии запрещён.
- Импорт сначала открывает отдельное окно предварительного просмотра: номер строки исходного файла, дата, тикер, тип, количество, цена, комиссия, статус и пояснение. До нажатия **«Подтвердить импорт»** операции не добавляются; «Отмена» и Escape закрывают просмотр. Источник читается один раз: добавляются именно показанные данные.
- Режим импорта — добавление к существующему журналу, без замены. Возможные дубликаты определяются по совпадению всех шести полей как с журналом, так и с предыдущими строками файла; по умолчанию пропускаются. Одинаковые реальные операции можно явно включить флажком. Для этого снова проверяется вся история, включая продажи по остаткам. Это эвристика совпадений, а не идентификаторы брокерских сделок.
- Неверная дата, отрицательные/пустые/нечисловые значения, неверный тип операции, повреждённые кавычки или продажа сверх остатка блокируют импорт целиком. Частичного молчаливого импорта нет. Комиссия обязательна; если её нет, укажите 0 явно. Количество — в акциях, **не в лотах**. Все цены и комиссии — в рублях; валютные операции этот формат не описывает.
- Операции сортируются по дате стабильно. Внутри одного дня сначала идут уже записанные операции, затем строки CSV в исходном порядке. Время сделок и ID брокера здесь не моделируются. Для внутридневной истории проверьте порядок строк; продажи не переставляются после покупок автоматически.
- Перед записью подтверждённого импорта создаётся проверенная резервная копия. При её ошибке импорт не выполняется. Журнал записывается атомарно, затем обновляется портфель в памяти. Если файл журнала изменился после открытия просмотра, требуется повторный импорт.
- Поддерживаются стандартные заголовки `date,ticker,side,quantity,price,commission` в любом порядке, CSV с `;` либо `,`, CRLF/LF, кавычки, UTF-8 BOM, десятичная точка или запятая (для CSV с разделителем `,` число с запятой нужно взять в кавычки). Дата — `YYYY-MM-DD`, тип — `BUY`/`SELL`, тикеры нормализуются к верхнему регистру. Лимит — 4 МБ и 10 000 операций за импорт. Произвольные отчёты брокеров ещё не поддерживаются: их сначала нужно привести к этому формату.
- Для импортированного тикера вне списка наблюдения операции сохраняются, но котировка и доля недоступны, пока бумага не добавлена в наблюдение и не обновлена. Импорт не добавляет тикеры в наблюдение скрытно.

Пример файла:

```csv
date;ticker;side;quantity;price;commission
2026-10-01;SBER;BUY;10;275.5;1.38
2026-10-02;SBER;SELL;2;280;0.28
```

## Надёжная основа 0.6.0

- `src/market_data.cpp` содержит WinHTTP, загрузку котировок, свечей, индекса и дивидендов. `src/storage.cpp` — файлы пользователя, атомарную запись, резервирование и кэш. Общие модели вынесены в `include/app_models.hpp`. В `main.cpp` остаются Win32-интерфейс, команды и отрисовка; дальнейшее разделение интерфейса будет поэтапным.
- Дневная история акций TQBR и IMOEX/SNDX сохраняется в `%APPDATA%\MOEXWatch\cache`. Кэш содержит тикер, режим торгов, дневной интервал, источник, время успешной загрузки, последнюю дату и число свечей. При старте история читается сразу, но считается устаревшей до подтверждения сетью; сохранённые свечи не подменяют свежую котировку и не запускают сигналы.
- После первого полного скачивания запрашивается хвост от предпоследней сохранённой сессии, чтобы обновить последнюю незавершённую свечу. Старые свечи вне окна 730 календарных дней удаляются при слиянии. Неверный формат, неполная или повторная страница, некорректный OHLC либо сбой сети не заменяют прошлый полный кэш. Повреждённый кэш перескачивается целиком. При недоступности сети основной интерфейс продолжает показывать сохранённые графики с пометкой устаревания; запуск бэктеста по неподтверждённой истории остаётся заблокирован.
- Кэш не содержит live-котировок. Дозагрузка обновляет две последние доступные сессии, а не пересчитывает возможные изменения старой истории MOEX; для полной повторной загрузки при закрытом приложении можно удалить соответствующий файл из `cache`.
- Кнопка **«Резервная копия»** находится сверху справа и доступна на всех вкладках. Сначала сохраняются текущие пользовательские записи, затем в фоне создаётся отдельная папка `%APPDATA%\MOEXWatch\backups\MOEXWatch-<метка>`. В неё входят `watchlist.csv`, `trades.csv`, `portfolio_transactions.csv`, `position_levels.csv`, `signals.ini` и сохранённые файлы дивидендов. Кэш свечей и EXE исключены. Содержимое каждой копии побайтово проверяется; неудачная копия не получает статус завершённой. Предыдущие копии не перезаписываются. После успеха открывается папка с инструкцией `RESTORE.txt`.
- Это локальная резервная копия на том же диске. Для защиты от поломки диска перенесите готовую папку на другой носитель. Восстановление: закрыть приложение, сохранить отдельно текущие файлы, скопировать файлы из выбранной копии обратно в `%APPDATA%\MOEXWatch`, затем запустить приложение. Автоматического импорта/объединения или восстановления одной кнопкой в этой версии нет.
- Все пользовательские записи заменяются через временный файл и атомарное переименование. Форматы журналов 0.5.2 сохранены, перенос данных не требуется. Ошибки файловой системы и повреждённые записи журналов больше не скрываются; после ошибки хранения автоматическая запись в этой сессии отключается для защиты оригиналов. Кнопка копирования остаётся доступна и копирует сохранённые файлы для восстановления.

Проверки: прежние тесты расчётного ядра и дивидендов плюс отдельные `storage_tests` — совместимость файлов, восстановление прибыли из копии, Unicode-пути, параллельное сохранение, исправление последней свечи, повреждённый/обрезанный кэш и отказ замены файла. Сборка Windows и CTest выполняются перед публикацией каждого релиза. Визуальная проверка интерфейса на Windows 10 проводится отдельно.

## Обновление из исходников на вашем компьютере

Закройте MOEX Watch. Распакуйте архив прямо в `D:\MOEXWatch`, заменив исходники. Архив не содержит вложенной папки проекта и не содержит готового EXE.

В Developer Command Prompt for VS 2022 выполните:

```cmd
cd /d "D:\MOEXWatch"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\build_windows.ps1"
start "" "D:\MOEXWatch\MOEXWatch.exe"
```

Скрипт проверяет сборку и тесты, затем копирует EXE прямо в корень проекта. Исходный EXE также остаётся в `build\Release`. Нужны Build Tools / Visual Studio 2022 с C++ MSVC v143, Windows SDK и CMake.

## Дивидендная аналитика 0.5.2

Исправлен источник: старый адрес `/iss/securities/<ticker>/dividends` возвращал карточку бумаги вместо дивидендов, хотя отвечал HTTP 200. Новый загрузчик использует открытые HTML-таблицы Smart-Lab: [общий календарь](https://smart-lab.ru/dividends/) и историю выбранного тикера `/q/<ticker>/dividend/`. Регистрация, подписка и ручной ввод не нужны. Для каждого события виден URL. Двойной щелчок открывает источник; двойной щелчок по столбцу «Эмитент» — официальный сайт.

- Кнопка «Дивиденды» в аналитике открывает отдельное окно с таблицей и независимыми вкладками графиков.
- События разделяются на «прогноз», «рекомендовано СД», «утверждено», «отменено» и историю с неподтверждённым статусом. Зелёная строка Smart-Lab сама по себе означает рекомендацию СД, а не решение акционеров. Прошедшая дата также не доказывает утверждение или факт выплаты.
- Первая автоматическая сверка подключена для **LKOH** по [официальной таблице ЛУКОЙЛ](https://lukoil.ru/InvestorAndShareholderCenter/Securities/Dividends). Дата реестра и сумма на акцию сверяются вместе. Несколько официальных выплат на одну дату суммируются перед сравнением. Совпадение подтверждает утверждённую сумму, но не зачисление денег на счёт. Расхождение показывается явно. Для остальных эмитентов проверка не подключена; при ошибке сайта ЛУКОЙЛ отображается «сверка не выполнена».
- Последний полный успешный набор сохраняется в `%APPDATA%\MOEXWatch\dividends_<TICKER>.csv`, включая источники, статусы, дату обновления и результат сверки. При перезапуске он показывается сразу с пометкой об актуальности, затем обновляется по сети. Запись заменяется атомарно. Неверный формат ответа, HTTP-ошибка или сбой одной из двух страниц не превращаются в пустой успешный календарь и не стирают сохранённый набор.
- Столбец «Последний день покупки» рассчитывается для **2026 года, TQBR/RUB/T+1**, по опубликованным расписаниям MOEX [n96571](https://www.moex.com/n96571) и [n95564](https://www.moex.com/n95564), проверенным 15.10.2026. Учтены неторговые дни, исключения и принадлежность дополнительных выходных сессий следующему основному торговому дню. Это встроенное расписание данной версии; при изменении регламента требуется обновление приложения. Срок не определяется простым вычитанием календарного дня.
- За пределами покрытия календаря расчёт показывает «н/д». Отдельный столбец «Купить до (источник)» сохраняет опубликованную Smart-Lab дату; она не выдаётся за собственный проверенный расчёт. В ядре есть поддержка T+2 для предоставленных исторических календарей, но встроенные календари других лет пока отсутствуют.
- Доходность указана до налогов: для будущих событий — к свежей текущей котировке, для истории — к закрытию рассчитанного дня покупки, только если доступна соответствующая свежая дневная история. Знаменатель подписан. Отменённым и противоречивым событиям доходность не рассчитывается. При недостатке данных — «н/д».
- На графике отмечается дата реестра, а не автоматически определённый дивидендный гэп. Прогноз помечается `D?`; отменённые и противоречивые события не рисуются. Если в дату реестра свечи нет, маркер отсутствует.
- Дивиденды пока **не включены** в фактическую прибыль портфеля и бэктест, включая прогнозы и рекомендации. Отдельный этап учёта выплат ещё предстоит.

Ограничения: календари могут быть неполными, запаздывать и менять структуру; при нераспознанном ответе загрузчик оставляет старые данные с ошибкой. Встроенное расписание не проверяет индивидуальные приостановки торгов по бумаге и особые ограничения брокера. Постоянного фонового сервера и скрытых ключей API нет; запросы выполняются приложением напрямую по HTTPS при открытии окна и нажатии «Обновить события».

## Портфель и метод расчёта

Покупка увеличивает остаток и среднюю себестоимость. Комиссия покупки включается в себестоимость: новая средняя цена равна (прежняя себестоимость + цена и комиссия новой покупки) / новый остаток акций. Продажа уменьшает остаток по средней цене; зафиксированная прибыль равна количество продажи × (цена продажи − средняя цена) − комиссия продажи. Частичная продажа оставляет среднюю цену неизменной. Бумажная прибыль оценивается как текущая рыночная стоимость оставшихся акций минус их себестоимость с учётом комиссий покупки; будущая комиссия продажи и налог не включены. Если котировка отсутствует, позиция остаётся в таблице без оценки стоимости и бумажной прибыли. Звёздочка отмечает устаревшую последнюю котировку.

Даты операций вводятся в формате `ГГГГ-ММ-ДД`. Операции сортируются по дате; при совпадении даты порядок добавления сохраняется. Налоговые годовые базы в версии 0.3 не рассчитываются. Старый журнал закрытых сделок остаётся в `trades.csv` отдельно и не смешивается с портфелем.

## Проверка стратегии

Правила оцениваются только по дневному закрытию. Покупка или продажа выполняется по открытию следующей общей торговой сессии для акции и IMOEX. Если позиция открыта в конце периода, она закрывается по последнему доступному закрытию. Расчёт использует дробные условные акции и полный капитал; налоги, проскальзывание, спред, лоты и дивиденды не моделируются. IMOEX — индекс цен, а не доходность конкретного инвестируемого фонда. Прошлый результат не подтверждает будущую доходность; тест нужен для изучения поведения правила, не является рекомендацией.

## Сигналы

Порог RSI задаётся от 0 до 100; правило «ниже» использует строгое `<`, «выше» — строгое `>`. Условие SMA200 — цена выше среднего за 200 дневных свечей. Близость к цели означает отклонение от целевой цены не больше заданного процента. В режиме «Все условия» каждая включённая проверка должна быть доступна и истинна; в режиме «Любое условие» достаточно одного совпадения. Сигналы скрываются при устаревшей котировке или истории и являются наблюдениями по прошлым/текущим данным, а не рекомендацией совершить сделку.

Пока приложение открыто, данные перепроверяются через выбранный интервал или по кнопке «Обновить». Уведомление отправляется при появлении нового совпадения после установленного базового состояния; постоянное совпадение не вызывает повторное уведомление при каждом обновлении.

## Расчёт сделок

Валовая прибыль = (цена продажи − цена покупки) × количество. Результат после комиссии = валовая прибыль − введённая общая комиссия. Оценка налога = положительная часть результата после комиссии × введённая ставка налога. Чистая прибыль = результат после комиссии − оценка налога. При убытке расчётный налог по этой сделке равен нулю.

Ставку налога пользователь вводит сам для каждой сделки; пустое поле означает 0%, то есть расчёт без налога. Это упрощённый ориентир, а не налоговый расчёт: он не учитывает налоговый статус, годовую совокупную базу, перенос убытков, льготы, дивиденды и прочие правила. Комиссия указывается общей суммой по покупке и продаже. В журнал вносятся закрытые сделки; приложение не ведёт FIFO-учёт отдельных лотов и не отправляет поручения брокеру.

## Расчёты и ограничения

RSI: первые средние роста/падения рассчитываются по первым 14 изменениям закрытия; следующие — `(13 * предыдущее среднее + текущее изменение) / 14`. Нулевая средняя потеря при росте даёт RSI 100, полностью неизменные цены — 50. ATR(14): истинный диапазон — максимум из `high-low`, `|high-предыдущее close|` и `|low-предыдущее close|`; первый ATR — среднее за 14 свечей, затем используется сглаживание Уайлдера. Объём сравнивается со средним 20 предшествующих дневных свечей; текущий день не входит в базу. Сравнение акции и IMOEX нормируется к 100 по первой общей дате выбранного диапазона. SMA — обычная средняя за соответствующее число свечей. Индикаторы считаются по всей загруженной истории, затем график обрезается до выбранного периода.

Фильтры по RSI и SMA исключают устаревшие котировки и историю. Фильтр целевой цены требует свежей котировки. Уровни RSI не являются рекомендацией купить или продать. Последняя дневная свеча может быть незавершённой; объём и RSI до закрытия сессии могут меняться. Приложение не делает собственную корректировку цен на дивиденды/сплиты и не отправляет сделки. Данные публичного ISS могут задерживаться, доступность отдельных блоков зависит от MOEX.

## Проверка

Portable C++ тесты проверяют CSV MOEX, RSI Уайлдера на контрольной последовательности, ATR Уайлдера, SMA50/200, нормирование и выравнивание сравнения по датам, расчёт отношения объёмов к предыдущим 20 сессиям, фильтры, расчёты сделок и режимы сигналов «любое/все», объяснения совпадений, устаревшие данные, некорректные пороги, портфель: средневзвешенная цена, комиссии покупок и продаж, частичная продажа, зафиксированная и бумажная прибыль, неверные даты и нехватка акций; бэктест: отсутствие заглядывания в следующий close, комиссии обеих сторон, сравнение с IMOEX и проверка пересечения дат. На Windows скрипт запускает эти же тесты через CTest. Workflow GitHub Actions собирает Win32-приложение с MSVC на Windows Server 2022 и запускает CTest при push и pull request. Визуальную работу интерфейса нужно отдельно проверить на Windows 10.
