## Включение GitHub Pages

Статический сайт находится в `docs/site`. Workflow `.github/workflows/pages.yml` собирает его вместе с `docs/screenshots` и публикует через официальный механизм Pages. Приложение и его пользовательские файлы не затрагиваются.

1. Settings → Pages → Build and deployment → Source → **GitHub Actions**.
2. Actions → **Project website** → Run workflow → main.
3. Дождаться успешного deploy и проверить адрес сайта. Только после этого установить Website в About.

На сайте нет аналитики, cookie-баннера, внешних шрифтов и JavaScript. Скачивание всегда ведёт на `/releases/latest`, без устаревающего номера версии в URL. Канонический адрес, Open Graph, robots.txt и sitemap.xml относятся к проектному адресу выше. При переносе репозитория их нужно обновить.

`robots.txt` на проектном сайте не заменяет правила корня домена GitHub Pages. Sitemap можно передать поисковым системам после подтверждения владения сайтом. Сроки и сам факт индексации не гарантируются.

## Обновление скриншотов

Actions → **Application screenshots** → Run workflow на нужной ветке. Workflow собирает Qt 6.8.3 на Windows, снимает настоящие экраны через `--demo --screenshot`, затем коммитит только `docs/screenshots/*.png` в выбранную ветку. Если ветка защищена, используйте отдельную ветку и PR. Нет реальных пользовательских операций, сетевых котировок и приватных данных. Скриншоты показывают синтетические демонстрационные данные, что подписано в README и на сайте.

После изменения версии или интерфейса переснять изображения и обновить подпись версии в README и `docs/site/index.html`.

## Публичное продвижение

Сначала проверить сборку, ссылки и Screenshots. Затем подготовить отдельные сообщения для тематических площадок с описанием реальных возможностей, ограничений и ссылкой на Releases. Публикации от имени владельца, выбор площадки и текст сообщения согласовываются отдельно. Никаких автоматических рассылок и накрутки поисковых ключей.
