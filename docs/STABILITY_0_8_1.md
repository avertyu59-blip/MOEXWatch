# MOEXWatch 0.8.1: стабилизация внутренних модулей

## Границы ответственности

- `PortfolioService` — типизированный журнал, ревизия, проверка импорта, операции и расчёт позиций. Не зависит от Qt/Win32.
- `MarketDataService` — загрузка кэша, сетевой адаптер, проверка и применение котировок/истории. Применение сохраняет локальные цели и не возвращает удалённые бумаги. Время жизни задач и доставка остаются у Qt-координатора.
- `WorkspaceSettings` — тема, выбранная бумага, период и сравнение графика. Неизвестная версия настроек не перезаписывается; ошибка настроек не блокирует финансовый журнал.
- `PortfolioController` — адаптация к QML, координация задач и построение моделей представления. Преобразование данных графика в QVariant остаётся здесь; это ещё не полное отделение всех страниц.
- `calculate_purchase_plan` — чистый C++-расчёт лотов, комиссии и сценарного риска с проверкой конечности промежуточных/итоговых значений.

## Уведомления и таблицы

Входы рынка, журнал, настройки, доступность записи, итоги портфеля и статус имеют разные события. Изменение темы или ручного остатка не запускает вычисление технических сигналов. Старый `changed()` сохранён для совместимости представлений, но расчётные модули больше не подписаны на него.

`RecordModel` сопоставляет записи по уникальным `id`, `key` или `ticker`. Обновляет данные и перемещает строки стандартными уведомлениями Qt, сохраняя persistent indexes. Полный `modelReset` не используется. Если у строк нет уникального бизнес-ключа, их нельзя достоверно сопоставить: для такого набора выполняются удаление и вставка строк, без обещания сохранения их личности. Для истории и дивидендных событий используются составные ключи.

## Хранение

Журнал v2 и JSON-файлы свободных средств, выплат, дневника и отчётности сохраняют прежние форматы. Общий `GuardedFile` сравнивает текущие байты с прочитанным снимком, перед заменой сохраняет предыдущие байты в `backups/last-good/<имя файла>`, проверяет копию и применяет атомарную замену. Конфликт внешнего изменения/удаления не уничтожает файл и не меняет модель в памяти. Для повторной проверки конфликтного файла нужен перезапуск.

Это проверка снимка под общей блокировкой профиля, а не файловая транзакция с произвольным внешним редактором. Последняя копия ограничена одной предыдущей версией каждого файла; она не заменяет отдельные пользовательские резервные копии профиля.

## Политика точности и следующие этапы

В 0.8.1 денежные форматы не мигрируют: сохраняются прежняя double-точность и сериализация с достаточным числом значащих цифр. Два знака в интерфейсе — формат отображения, не округление каждой операции. Полноценный денежный журнал потребует отдельного типа Money, явных правил округления RUB до копеек и независимой точности цен/количества инструментов; миграция будет выполняться с резервной копией и сверкой результата. Массовая замена double на int без политики округления не выполняется.

История фундаментальных периодов также потребует отдельной версии хранилища и выбора периода в UI. Текущая запись на тикер и формат v1 сохраняются. Исторические данные, уже заменённые раньше, автоматически не восстанавливаются.

Поставщик торгового календаря явно сообщает покрытие 2026-01-01…2026-12-31. Даты вне покрытия получают пустой календарь; последнее число покупки не угадывается по дням недели. Расширение календаря требует проверенного источника.

## Проверки

Добавлены проверки чистого расчёта покупки, конфликтов сохранения и last-good копии, ревизии/перезапуска журнала, сортировки с QPersistentModelIndex/QItemSelectionModel, неизвестной версии настроек и отсутствия пересчёта сигналов при визуальных изменениях. Windows CI отдельно собирает реальную CMake-цель `moexwatch_quick`, не снимая и не публикуя изображения.

Физические Windows 10, несколько мониторов, разные GPU и DPI не заменяются offscreen-проверками. Прежние скриншоты 0.8.0 в README и на странице проекта оставлены без изменения.
