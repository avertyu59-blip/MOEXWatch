# Подпись Windows EXE

`.github/scripts/sign-windows.ps1` подписывает только указанный EXE
сертификатом Code Signing из `Cert:\CurrentUser\My`. Закрытый ключ не
передаётся в аргументах, не экспортируется и не хранится в репозитории.
Нужен Windows SDK с SignTool, действующий сертификат с доступным закрытым
ключом и HTTPS-адрес RFC3161 timestamp-сервиса, поддерживаемого поставщиком.

```powershell
.\.github\scripts\sign-windows.ps1 `
  -FilePath 'D:\MOEXWatch\package\MOEXWatch-Qt.exe' `
  -CertificateThumbprint '<40 шестнадцатеричных символов>' `
  -TimestampUrl '<HTTPS URL сервиса временных меток>'
```

Скрипт использует SHA256 для файла и RFC3161 timestamp, проверяет цепочку
доверия через `signtool verify /pa /all`, статус Authenticode, ожидаемый
отпечаток издателя и наличие временной метки. При любой ошибке публикация
останавливается. Самоподписанный сертификат не заменяет доверенную подпись.

## Публикация

В release workflow предусмотрены переменные репозитория:

- `MOEX_SIGNING_CERT_THUMBPRINT`: отпечаток установленного сертификата.
- `MOEX_SIGNING_TIMESTAMP_URL`: адрес сервиса временных меток.
- `MOEX_REQUIRE_SIGNING=true`: запрещает публикацию без настроенной подписи.

Это идентификаторы/настройки, не закрытые ключи. Сертификат и провайдер ключа
должны быть доступны пользователю, под которым работает Windows runner.
На стандартном GitHub-hosted runner их по умолчанию нет. Одного добавления
переменных недостаточно. Для аппаратного токена или облачного сервиса нужен
совместимый провайдер ключа и отдельное подключение с учётом правил CA.
Текущий workflow не импортирует PFX и не настраивает облачную подпись.

Подпись выполняется после deployment, до упаковки и SHA256SUMS; после
распаковки подпись проверяется повторно. В release notes явно указывается,
подписан ли EXE. Библиотеки Qt/MSVC не переподписываются.

Нельзя утверждать, что релиз подписан, до успешного нативного запуска
подписи. Сертификат для этого проекта пока не подтверждён. Покупка,
проверка личности издателя и получение сертификата не выполнялись.

## Проверки

Windows CI проверяет синтаксис PowerShell, отказ от неверного отпечатка,
небезопасного timestamp URL и отсутствующего сертификата без изменения EXE.
Эти проверки не заменяют успешное подписание настоящим сертификатом.
